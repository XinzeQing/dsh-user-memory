# 多功能记忆（dsh-user-memory）

自研的 DeepSeek Harness 插件：把**用户本人编写**的分级长期记忆注入到系统提示词里，并提供一个**中文图形面板**供直接查看和修改；另有**工作流**与**短期目标**两套可切换模式，按会话生效。

> **本文的称呼约定**：AI 一律写「AI」、用户一律写「用户」，全文不拿「我／你」指代任何一方。引号里是界面或注入文本的**原文**，人称按原文自身语境——注入给模型的那几段里，「你」指模型、「用户」指用户。
> 文中的 `<DSH_HOME>` 指 DSH 的数据目录（默认 `%USERPROFILE%\.dsh`），`<profile>` 指 profile 名（例如 `desktop`）；凡写进 `<...>` 的都是占位符，不是本机的真实路径。

- **宿主插件**：profile 加载它，每一轮都在。
- **运行时只读**（除用户操作外）。它从不自行写记忆：只有两条写入路径——用户在面板里点保存，或用户让 AI 用文件工具改。没有自动采集、自动总结、后台回写、网络访问。
- **AI 只能提议，不能决定**：`memory_suggest` 把一条建议放进「待确认」区，**只有用户在面板里点「采纳」**，它才变成一条通知，AI 下一轮才去写。
- **零依赖**，只用 Node 内置模块。整个目录拷到哪都能跑。
- **三层记忆**：长期记忆回答「用户是谁、AI 该怎么干」，**临时记忆**（默认关）回答「这件事还没做完、交给谁」，**工作流 / 短期目标**回答「这次按哪套做法干」。临时记忆是**第二段**系统提示词、**另一份**预算，做完归档就立刻从上下文里消失；工作流与短期目标是**按会话**注入的两个小段，不选就不存在。

## 图形面板（推荐用这个）

重启 DeepSeek Harness 之后，**左侧栏**会出现一个「**多功能记忆**」入口，点开就是面板：

- 九个分页：**必须遵守** / **行为设定** / **用户画像** / **可选遵守** / **变更日志** / **工作流 / 目标** /（`tempMemory: true` 时）**临时记忆** / **待确认** / **设置**；全部中文，不用看文件名。「待确认」分页固定在倒数第二个，「设置」永远在最后。
- 打开时停在**临时记忆**分页（它是最常动的那一页），并记住上次停在哪个分页，下次打开直接回到那里。`tempMemory: false` 的 profile 没有这一页，打开就停在「必须遵守」。（上次的分页记在浏览器本地存储 `dsh-user-memory:active-tab` 里，清掉它就恢复默认。）
- 「待确认」与「临时记忆」两个分页各带一个数字气泡，表示各自还有多少条要处理。
- 记忆文件按**条**编辑（0.8.2）：一条记忆 = 一张卡片（一个 `- ` 列表项，或一个段落），组名与文件标题也能改。点「保存这一节」整份发回，服务端重新串成 markdown——**逐字节可逆**，手写的空行、缩进、注释不会被面板重排。**保存后立即生效，不需要重启**；底部回显结果，例如「已生效：这一节 M 条会整节注入（约 320 字）。」，回显同时给出整块用量与保留比例（「目前整块注入约 4176 字：记忆共 5100 字，保留 81%；预算 6000 字。」）。
- **失真提示**：编辑器顶部一行写「这一节 N 条全部会进上下文」或「N 条里只有部分进上下文（X / Y 字，保留 Z%）」并配进度条；没进上下文的条目标「这次没进上下文」（单条本身超过剩余预算时也是整条不进，不会切半句）。分页标签上出现橙色「!」表示这一节有内容没进上下文。**有未保存改动时这些标记会暂时隐藏**——它们描述的是磁盘上的旧内容，不该拿来标新编辑的条目。
- 有未保存改动的分页显示一个小黄点；「放弃改动」可一次性还原。
- 只认那五个文件名，其它路径一律拒绝；单个文件上限 256 KB。
- 顶部有一个「**自动提议提醒：已开启 / 已关闭**」开关（见下面 `autoCapture`）。

### 待确认区（AI 与用户之间的闸门）

1. AI 用 `memory_suggest` 提议一条：目标文件 + 完整措辞 + 理由。**这个工具不写任何记忆文件**，只在 `<DSH_HOME>\memory-suggest.json` 里放一条 `pending`。
2. 用户打开面板 →「待确认」→ 看到卡片。卡片下方有一个**「补充说明」输入框**（可选）：想额外加的要求、想改的措辞写在这里。
   - **打字不落盘**：输入框里的字只在点「采纳」或「不采纳」的那一刻才随这条存下来（存进 `userNote`），所以犹豫期间磁盘上没有任何痕迹；自动刷新也不会擦掉正在打的草稿。
   - 采纳与不采纳都会带上补充一起交给 AI，**与 AI 原文冲突时以补充为准**。补充上限 1000 字符，自动去掉首尾空白。
3. **三个动作，不是一个闸门开关**：**采纳** / **不采纳** / **忽略**。
   - **采纳**：下一次发消息时 AI 收到 `<MEMORY_SUGGESTION_ACCEPTED>`，到那时才总结措辞、写进记忆文件，并调用 `memory_suggest_done` 记账。
   - **不采纳**：AI 收到 `<MEMORY_SUGGESTION_DECLINED>`，明确「这条不要写进记忆」，并把它当作用户的纠正读——补充里通常写着「为什么不采纳 / 正确做法是什么」。它**不会被写入**，但 AI 会知道「这条被否过」，不会过两天再提一遍。忽略做不到这一点：忽略是静默的，AI 什么都不知道。
   - **忽略**：直接丢掉，不通知 AI、不留理由。适合「这条根本不值得讨论」。
   - 三者都**不动记忆文件**；真正的写入永远发生在 AI 收到通知之后。
4. 通知**只送回提这条建议的那个会话**（记在 `originSession` 里）：在别的会话里做决定，不会让无关对话突然收到一条没头没尾的「去写记忆 / 不要写」。若那个会话半小时内都没再说话，通知改由下一个开口的会话领取，免得永远搁着。
5. **反悔窗口**：「采纳」与「不采纳」在 AI 下一轮还没开始之前都能撤销——采纳的回到 `pending` 并保留补充，不采纳的也回到 `pending` 并清掉写了一半的补充。一旦通知已经交到 AI 手里（状态变成「通知已送达 · 处理中」），撤销按钮就没了，并说明原因；如果点撤销的那一刻 AI 刚好开跑，服务端会如实拒绝并告知。
6. 两种例外 AI 会**先停下把 diff 摆出来**：措辞与用户采纳的原文有实质差异；或这条与文件里已有内容重复、冲突。

面板**一直**每 5 秒刷新一次「待确认」与「临时记忆」的状态，不只在停在两个分页的时候——所以停在别的分页，标签上的数字气泡也会跟着变：AI 在另一个会话里写入一条临时记忆，或提议了一条新建议，面板不用重开就能看见。正在输入框里打的草稿不会被刷新擦掉。**沉默 = 放弃**：提议完 AI 就回去干手里的活，不催促。（`memory-suggest.json` 里最多留 80 条：未决定的一条都不丢，已决定的从最旧的开始丢。）
| 工具 | 干什么 | 会不会写记忆 |
|---|---|---|
| `memory_suggest` | 提议一条（文件限那五个，正文上限 4000 字符，单条可带一句理由） | **不会** |
| `memory_suggest_done` | 处理完一条后记账：写进了哪个文件，或为什么不写 | **不会** |

## 记忆库在哪（也可以直接改文件）

```
<DSH_HOME>\memory\
├── rules-must.md      必须遵守（硬性）   ← 注入
├── agent.md           行为设定           ← 注入
├── profile.md         用户画像           ← 注入
├── rules-should.md    可选遵守（酌情）    ← 注入
├── log.md             变更日志            ← 不注入，只给用户自己记账
└── modes.json         工作流 / 短期目标   ← 按会话注入；第一次保存模式时才创建
```

第一次启动时，缺失的文件会用内置模板创建——模板里是 `<!-- -->` 注释说明，不注入；**已经存在的文件从不覆盖**。

直接记事本改也行，效果与面板完全一样——**文件是唯一真相**。

## 注入规则（决定它花多少 token）

| 行为 | 说明 |
|---|---|
| 注入位置 | 系统提示词的一个段落，`order = -500`：**Harness 身份之后、人格设定之前** |
| 顺序 | 必须遵守 → 行为设定 → 用户画像 → 可选遵守 |
| `<!-- -->` 注释 | **永远不注入**。所以模板里的说明文字不占上下文、不干扰 AI |
| 只有标题没有正文 | **整节不注入**。空文件 = 零开销；文件都没内容则整块不注入 |
| token 成本 | 记忆不变时系统提示词逐字节不变 → **吃满 prompt cache**；改了才会有一次新快照 |
| 预算 | `maxChars` 默认 6000 字符。**按条目装填**（0.8.2）：一条记忆整条进上下文，或整条不进——不会把一句话切成两半；某条放不下就跳过它去试后面更短的条，全部试完还装着的就不进。最后按实际缺口追加一句固定说明：「另有 N 条记忆这次没有进上下文，全文见 <记忆目录的绝对路径>」；这句也放不下时从尾部逐条驱逐已装条目，直到腾出位置。整节都装不下时连标题一起不出现。不再存在「只进了前半句」的静默截断 |
| `autoCapture` | 默认关。关着时一个字都不多注入；打开后末尾多一段**固定**提醒，且**不算进 6000 预算** |
| 第二段（临时记忆） | `order = -490`，紧跟在这一段之后，有**自己的** `tempMaxChars` 预算；只有没归档的条目进，归档即消失。默认整段不存在 |
| 第三段（工作流） | `order = -485`，**按会话**注册在 agent 作用域里；没选（且无默认）时整段不注入 |
| 第四段（短期目标） | `order = -480`，同上，但没有默认——不选就没有 |

## 临时记忆（跨对话的活跃工作集）

长期记忆是用户写给 AI 长期遵守的；临时记忆是**这一阵子没做完的活**——跨对话交接、阶段性目标、等条件满足才做的待办。

| kind | 用来干什么 | 什么时候清掉 |
|---|---|---|
| `handoff` 交接 | 一件事交到别的对话手里（换会话执行）。**正文可以写长、写全：它同时就是交付文档**。注意长文不等于一定进上下文——见下面「预算独立、超了只点名」 | 接手方做完后归档 |
| `stage` 阶段目标 | 眼下的阶段性目标，省掉在多个对话里重复说明 | 阶段结束 |
| `waiting` 等待项 | 等条件满足再执行（CI 绿了、文件到了、用户确认了……） | 条件满足、执行完 |

- **只在用户要求时写**。只有用户说出「写临时记忆 / 记到临时记忆 / 交付记忆 / 换会话执行 / 下次对话接着做」，AI 才调用它；**其余一律不调**——不自动总结、不顺手记、不后台回写。
- **完成即清理**。调用 `temp_memory_done` 之后它**立刻不再注入**；数据留在盘上做归档（保留 30 天内、最多 20 条；没归档的一条都不剪），要物理删除得在面板里点「删除」。
- **存在 `<DSH_HOME>\temp-memory.json`**，不在记忆目录里——它要跨对话，就得让所有会话共用一份。**只有第一次写入时才创建这个文件**。
- **预算独立、超了只点名**：`tempMaxChars`（默认 1200）只管这一层，与四层正文的 `maxChars` 互不挤占。装不下整条的**不会被截一半塞进去**，而是只留一行 `#id 全文见 <路径>`——半截的交付文档比一个指针更糟。**最新优先**：预算不够时最晚更新的一条先保住。
- **文本是常量**：没条目时整段不注入；有 `waiting` 时才追加一小段固定提醒。绝不把时间、条数之类每轮都在变的东西写进注入文本，否则 prompt cache 每轮失效。
- **不保证「到点自动执行」**。DSH 没有常驻观察者：`waiting` 做到的是「AI 在对话里能看到它，条件满足就直接做、做完归档」。要真正的定时/条件触发用 `schedule_create`，本插件**不做，也不假装做了**。

| 工具 | 干什么 | 会不会写记忆 |
|---|---|---|
| `temp_memory({kind,title,body})` | 写一条，返回编号；**下一个模型步骤就出现在上下文里**。标题上限 200 字、正文上限 8000 字 | 只写 `temp-memory.json`，不碰那五个记忆文件 |
| `temp_memory_done({id,note})` | 归档一条（`note` 写结果），**立刻停止注入** | 同上 |

面板里的「临时记忆」分页（`tempMemory: true` 时才出现）：看 / 改 / 新增 / 标记完成（归档）/ 恢复为活跃 / 删除 / 清空归档，一处点完，**不用重启**。「待确认」分页仍然固定在最后一个。

**什么时候才需要重启**：只有两种情况——改了 `index.js` / `client.js`（加载器用裸 `import()`，Node 的 ESM 模块缓存不会失效）；或者**手工编辑 `temp-memory.json`**（宿主在启动时把它读进内存，之后只认自己写的那份，手工改动要等下次启动才被看到）。AI 用 `temp_memory` 写、用户在面板上点、别的会话写入，都不需要重启：宿主写完立刻重算注入文本，下一个模型步骤就带上。

## 工作流与短期目标（按会话切换）

长期记忆是「永远该这样」，临时记忆是「这一阵子没做完的活」；**工作流**是「这一类活按哪套做法干」，**短期目标**是「眼下这一阵子要达成什么」。两者都是用户自己写的模式，一个模式 = 一个名字 + 一段正文，**不选就什么都不注入**。

- **入口在会话窗口里**：输入框上方那一排工具按钮的最左边，多出两个 chip——「**工作流**」和「**短期目标**」。点开就能选，**换会话各记各的**，也随时能在会话中途换（下一个模型步骤就生效）。
- **工作流有默认**：面板「工作流 / 目标」分页可以把某一条「设为默认」，之后新会话、没单独选过工作流的会话都用它。chip 里显式选「**不用**」可以关掉默认；选「**跟随默认**」则回到默认。
- **短期目标没有默认**：不选就完全不加，chip 显示「不选」。这项是用户原话要求的「短期目标没有默认，不选就无视」。
- **写在哪**：`<DSH_HOME>\memory\modes.json`——与记忆文件同目录。**第一次保存模式时才创建**；没写过就没有这个文件，注入也是零开销。
- **注入成两段独立小节**：工作流 `order = -485`、短期目标 `order = -480`，排在长期记忆（-500）与临时记忆（-490）之后。文本形如：

  ```
  ## 当前工作流：硬件模块验证

  （用户写的正文）
  ```

  没选、或正文本只剩注释时，该段整段为空、不注入。
- **面板里能新建 / 编辑 / 删除 / 设默认**；删除一条会同时清掉「默认」和所有会话对它的选择，不会留下悬空引用。
- **不选不影响长期记忆**：两套模式都是追加的小段，空着的时候系统提示词逐字节不变。

## 让 AI 写记忆（两条流程）

1. **「记住…」** → AI 把内容整理成条目，**先把 diff 摆出来**，用户确认后才落盘。
2. **「整理记忆」** → AI 把这段时间的沉淀批量整理出来，同样先给用户审。

## 配置

在 profile 的 bundle patch 里（`cordis.patch.yml`）：

```yaml
- insert:
    - id: user-memory
      name: 'dsh-user-memory'
      config:
        enabled: true     # false = 停用注入，不卸载
        dir: ''           # 空 = <DSH_HOME>/memory
        maxChars: 6000    # 注入总预算（含前言与截断提示）
        autoCapture: false  # true = 打开「自动提议提醒」
        tempMemory: false   # true = 再挂一段「临时记忆」
        tempMaxChars: 1200  # 只给上面那一段的预算，与 maxChars 互不占用
```

改完需要**重启**才对 composition 生效；只改记忆文件内容则不需要。

> **实测注意：profile 里的 `config:` 是「整块替换」，不是逐键合并。**
> 在 `<DSH_HOME>/profiles/<profile>/cordis.patch.yml` 里写 `- id: user-memory` + `config:` 时，列出的键会**顶掉** bundle 里的整套 config。比如只写 `autoCapture: true`，读回来的就是 `config: { autoCapture: true }` —— `dir` 和 `maxChars` 都不见了（退回内置默认值）。
> 所以覆盖时**把需要生效的键一次写全**：`enabled` / `dir` / `maxChars` / `autoCapture` / `tempMemory` / `tempMaxChars`。
> （桌面版的 profile 由 App 自己管，命令行未必读得到它的 composition；这种情况就靠重启后看面板——那个新分页出现、且不是「未启用」，就是生效了。）

### `autoCapture`：要不要让 AI 主动提建议（默认关）

> 名字先说清：面板上这个开关叫「**自动提议提醒**」，注入段落里那一小节标题仍是「记忆采集提醒」——前者是给人看的，强调**只提议、不落盘**；后者是给模型看的原话，措辞不动（改它只会白白让一次 prompt cache 失效）。这个开关**从不**自己采集记忆。

**默认 `false`。关着的时候，注入的提示词与没有这个开关时逐字节相同——一个字符都不多。**

开关在面板顶部（**不用切分页，打开面板就在**），点一下就切换，**不需要重启、不需要改配置文件**——它写的是 `<DSH_HOME>\.autocapture` 这一个文件（内容就是一个 `on` 或 `off`），宿主每轮读到它就把注入段落同步过去，**下一次发消息**时就能看到效果。

优先级顺序：`.autocapture` 文件 > `config.autoCapture` > 内置默认 `false`。文件里认 `on` / `off`（也接受 `1` / `true` / `0` / `false`，不区分大小写、忽略首尾空白）；写了别的内容（例如手改坏了）等于「没有意见」，自动退回看配置——不会因为一个字写错就静默关掉整个功能。反过来，**一旦在面板上点过，`.autocapture` 就一直盖住配置文件**；想交还给配置，删掉那个文件即可。

也可以走配置文件（老办法）：把 `config:` 里的 `autoCapture` 写成 `true`，然后**重启 App**。适合一开始就想默认打开、或者要写进 dotfiles 的场景。

打开后，注入段落的**末尾**会多出这一小节固定文本：

```
## 记忆采集提醒（开关已打开）

- 本次对话中若发现值得长期记住的用户偏好或规则（明说的要求、反复出现的偏好、明确的禁止项），调用 `memory_suggest` 把它放进待确认区。
- 不要直接改记忆文件：用户点了「采纳」才会真正写入。
- 只提你确实观察到的，不要为了凑数而提。
```

要点：**不占预算**（这段提醒不算进 `maxChars`，打开它不会挤掉记忆内容）；**文本是常量**（内容写死在插件里，绝不随对话变化，否则 prompt cache 每轮失效，比多这几十个字贵得多）；**只是提醒，不是强制**（不保证每轮都调，也不会让 AI 越权直接写文件）。这个开关**只动注入文本**：它不写记忆文件、不碰待确认区。「AI 从不自行写入」照旧。

## 安装

profile 用 `link:` 依赖指向插件目录（不拷贝），装好后 `<DSH_HOME>/profiles/<profile>/node_modules/dsh-user-memory` 就是那个目录的 junction：

```json
// <DSH_HOME>/profiles/<profile>/package.json
"dsh-user-memory": "link:<插件目录>"
```

**每个 profile 各装一次**：profile 之间互相独立，装到哪个 profile 就只在哪个里生效。改代码改的就是插件目录里的文件。

## 0.8.4：三个动作、一个提示点、一层对比度

1. **待确认区从两个动作变成三个**：**采纳 / 不采纳 / 忽略**。以前只有「采纳」和「忽略」，用户想表达「这条不对，但我想告诉他为什么」时没有出口——打好的补充说明只能跟着「采纳」走，或者被一起丢掉。
2. **「不采纳」是一条真通知**。它生成 `<MEMORY_SUGGESTION_DECLINED>` 交给 AI，逐条带上原建议、理由与用户的补充，并写明「不要把这些内容写进记忆文件」「带补充的条目按补充处理」「不要重提同一条建议」。状态是 `declined`，**不是** `accepted`，也与 `dismissed`（忽略，静默丢弃）分开记。投递沿用 0.8.1 的按会话规则（`originSession` + 半小时兜底），送达后只写 `declinedDeliveredAt`，状态保持 `declined`；送达前可以撤销回 `pending`，送达后服务端拒绝撤销（409）。
3. **左侧「多功能记忆」图标上的提示点**。面板通常关着，待确认区里有没有东西在等你决定，以前只有打开面板才知道。现在图标右上角会有一个点：它每 10 秒问一次服务端还有多少条 `pending`，做决定后立刻消失（面板广播一个本地事件，不必等下一轮轮询）。侧栏插槽不提供 badge 字段，所以这个点由图标自己画；颜色跟随主题的正文色（深色主题下是浅色点、浅色主题下是深色点），靠一圈页面底色的描边分离出来，不是写死的红色。
4. **提示点可以关**。设置页最顶上的一节是「提示」：「待确认区有未处理的建议时，左侧「多功能记忆」图标显示红点」，默认开，与其他视图设置一起存在浏览器 localStorage（`dsh-user-memory:ui` 的 `dot`）。关掉只是不再提醒：队列、数字气泡、注入行为都不变——这个点从不写记忆、不进上下文、也不通知 AI。
5. **标签页上的数字气泡在任何主题下都看得清**。原来用 `brand-primary` 做底、`label-inverse` 做字色；DSH 的主题 token 里没有 `label-inverse`，字色一律落到代码里写死的 `#fff`，主题把品牌色配成浅色时就成了白字压浅底。现在换成一对互为正反的 token：底色 `label-primary`、字色 `bg-base`，再加粗一点。
6. **测试**：66 / 63 / 72 / 31 / 124，五个文件全绿。

## 0.8.3：面板与宿主版本错位时不再误导人

这一版只修两处「看起来像坏了、其实没坏」的地方。

1. **面板比宿主新时不再显示成「记忆空了」**。浏览器里的客户端会随插件热更新，而 DSH 主进程只有在重启时才换新 `index.js`。中间这段时间里，旧宿主返回的数据没有 `doc`（条目结构），面板若按空文档渲染，长期记忆看起来就像被清空了。现在 `load` 一旦发现某个文件没有 `doc`，就进入「只读原文」状态：顶部写明「记忆文件都在，只是面板比宿主新」，正文直接显示文件原文，并标明目录；这时**保存会被拦下**并提示先重启，避免用空文档覆盖真文件。
2. **「临时记忆」页不再点一下就弹回**。0.8.2 加过一条逻辑：宿主报告 `tempMemory: false` 时，一打开这一页就自动切回第一个文件页。实际体验是点一下高亮闪一下又跳走，像「点不进、卡一下」。现在标签页保留，点进去直接说清楚「没有启用、开关在插件配置里、改完要重启」。
3. **测试**：66 / 55 / 72 / 31 / 109，五个文件全绿。

## 0.8.2：记忆按条编辑 + 视图设置 + 失真提示

1. **一条记忆一张卡片**。文件不再是一个大文本框：每个 `- ` 列表项（含缩进续行）或段落是一个条目，`## ` 行是一个可命名的组，`# ` 行是文件标题。可以逐条改、逐条删、在组内加一条、新增一组。真正的好处不是好看：有了条目边界，才谈得上「哪一条进了上下文、哪一条没进」，也才谈得上以后的卡片/索引/视图。
2. **保存仍然逐字节可逆**。面板编辑的是一份 `doc` 结构，「保存这一节」把它整份发回服务端，由 `composeDoc` 重新串成 markdown。原文件里的空行数、缩进续行、`<!-- -->` 注释都原样保留——这一点在真实的五个记忆文件上验过：解析再串回，与原文件逐字节相同。手写与 git diff 都还能用。
3. **注入按条目装填，不再切句子**。以前预算不够时会把一节从中间截断；现在一条记忆要么整条进，要么整条不进，某条放不下就跳过它去试后面更短的，装完再按实际缺口补一句「另有 N 条没有进上下文，全文见 <路径>」。整节都装不下时连标题一起不出现。单条本身超过整个预算时也是整条不进，不会出现半句话。
4. **失真程度直接写在脸上**。编辑器顶部给出「这一节 N 条全部会进上下文（X / Y 字）」或「只有部分进上下文（保留 Z%）」+ 进度条；页头给出整块口径「整块注入 X / Y 字（保留 Z%，预算 B 字）」；没进上下文的条目带红色描边与「这次没进上下文」；分页标签上有橙色「!」。有未保存改动时这些标记暂时隐藏，因为 report 描述的是磁盘上的旧内容。
5. **设置页：按需隐藏标签页**。四个预设（全部 / 简洁 / 工作 / 游戏）+ 每个标签页一个勾选框，改过就是「自定义」。设置只存在浏览器 localStorage（`dsh-user-memory:ui`），**只影响面板显示，不影响注入**——藏起来的记忆照旧每轮进上下文；这条边界在设置页里也写着。设置页自己永远可见，否则藏了入口就没处改回来。
6. **接口**：`load` 每个文件多返回 `doc`（解析结构）与 `entries`（条数），并带整块的 `injection` 报告；新增 `saveDoc`（收 `{file, doc}`，服务端重建受控形状后写盘）；旧的 `save`（收 `{file, content}`）原样保留，作为兼容入口。
7. **测试**：66 / 55 / 72 / 31 / 109，五个文件全绿。

## 0.8.1：只修 bug（功能一个没动）

1. **面板保存回显不再一律说「已生效」**。以前这一节被预算截断、甚至整节没进上下文，回显也是「已生效：这一节会注入（约 N 字）」。现在回显带整块用量（「目前整块注入约 4176 / 6000 字」），并如实区分「只有开头约 K 字会注入」与「这次没有被注入」——「已生效」三个字只在真的全量注入时才出现。
2. **截断提示带上记忆目录的绝对路径**。注入文本里那句「完整内容见记忆目录」以前没有路径，模型没法照着去找；现在写成「完整内容见 `<dir>`」。预算小到放不下这条带路径的提示时，退回原来的短提示，截断照样会告知。
3. **采纳通知按会话投递**。`memory_suggest` 现在记下 `originSession`，`<MEMORY_SUGGESTION_ACCEPTED>` 只送回**提这条建议的那个会话**；在别的会话里采纳，不会再让无关对话突然收到一条「去写记忆」。原会话半小时都没再说话时，通知由下一个开口的会话领取，不会永远搁着。0.8.0 存下的老条目没有这个字段，仍按「谁下一个说话谁收到」处理。
4. **开关改名**：面板上的「自动采集记忆」→「**自动提议提醒**」。它从来没自动采集过，旧名字容易被读成「AI 会自己写记忆」。注入文本里那一小节标题（「记忆采集提醒」）没动——那是给模型看的原话。
5. **启动日志摊开解析后的配置**：`dir` / `maxChars` / `autoCapture` / `tempMemory` / `tempMaxChars` 全部打印。profile patch 的 `config:` 是整块替换，只写一个键会把其余键顶回默认值；以前这种「配置悄悄变回默认」只能靠猜，现在日志里看得见。
6. **临时记忆的工具说明与实际预算对齐**。以前写「正文可以写长、写全」，与 1200 字的临时预算冲突；现在说明白：长文不一定进上下文，装不下的条目只留 `#id` 和文件路径。

当时自测项数：57 / 55 / 72 / 31 / 90，五个文件全绿（见下）。

## 完全卸载 / 回退

在插件图形管理器里移除 `dsh-user-memory` 这个 bundle（AI 侧对应的动作是 `plugin_manager` 的 `remove_bundle`）。

插件消失，**记忆库 `<DSH_HOME>\memory\` 不会被删**（数据与代码分离）。想彻底清干净就再手删那个目录。

## 已知边界

1. **「必须遵守」不是技术强制**。插件只能把规则放进系统提示词的强位置，不能让模型永不失误。写得具体、可判定、够短，比写得多更有效。
2. **改代码需要重启**。加载器用裸 `import()`，Node 的 ESM 模块缓存按路径记账且不失效——改 `index.js` 或 `client.js` 后必须重启 App。**改记忆文件不需要**。
3. **profile 相互独立**。每个 profile 有各自的 `node_modules`，插件要各装一次。
4. **界面文案硬编码中文**。不走 locale 服务——单语言自用插件的取舍（`locale/` 里有 en/zh 两份 JSON，但面板文案不读它）。
5. **临时记忆不跨进程同步**。`temp-memory.json` 由**拥有它的那个进程**在内存里维护。手改这个文件、或同时跑两个进程时：磁盘上的改动要**下次启动**才生效，而且**下一次写入会覆盖手改的内容**——要改它请用面板。
6. **`waiting` 不是调度器**。没有常驻观察者，条件是否满足由 AI 在对话里判断；要真正的定时/条件触发请用 `schedule_create`。
7. **chip 依赖 Harness 自带的 Menu 组件**。`@deepseek-ai/dsh-client-ui-primitives` 取不到时，两个 chip 自动降级成原生 `<select>`，功能不丢，只是没有菜单样式。
8. **工作流 / 短期目标与 agent preset 是两回事**。agent preset（标准 / 极简 / 创造…）改的是**整个会话怎么被组装**，只能在新建会话时选；工作流改的只是**额外注入的一段话**，会话中途可换、每个会话各记各的。
