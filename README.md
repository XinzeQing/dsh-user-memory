# dsh-user-memory

自研的 DeepSeek Harness 插件：把**用户本人编写**的分级长期记忆注入到系统提示词里，并提供一个**中文图形面板**供直接查看和修改。

> **本文的称呼约定**：AI 一律写「AI」、用户一律写「用户」，操作步骤用祈使句（「打开面板，点『采纳』」），全文没有拿「我／你」指代任何一方。引号里是界面或注入文本的**原文**，人称按原文自身语境——注入给模型的那几段里，「你」指模型、「用户」指用户。

- **宿主插件（Host plugin）**：只要 profile 加载它，每一轮都在。
- **运行时只读**（除用户操作外）。它从不自行写记忆：只有两种写入路径——用户在面板里点保存，或用户让 AI 用文件工具改。没有自动采集、自动总结、后台回写、网络访问。
- **AI 只能「提议」，不能「决定」**：AI 可以把一条修改建议放进「待确认」区（`memory_suggest` 工具），但**只有用户在面板里点「采纳」，它才会变成一条通知，AI 下一轮才去写**。见下面「待确认区」。
- **采纳前后都能反悔**：卡片上有一个「补充说明」输入框，采纳时它与 AI 的原文一起交给 AI（冲突时以用户的补充为准）；采纳后、AI 下一轮开跑之前，卡片上会多一个「撤销采纳」，点它就回到待确认，补充还能改。
- **零依赖**，只用 Node 内置模块。整个目录拷到哪都能跑。
- **另有一层「临时记忆」（0.7.0，默认关）**：长期记忆回答「用户是谁、AI 该怎么干」，它回答「**这件事还没做完、交给谁**」——跨对话交接、当前阶段目标、等条件满足才做的待办。它是**第二段**系统提示词、**另一份**预算，做完归档就立刻从上下文里消失。见下面「临时记忆」一节。

## 图形面板（推荐用这个）

重启 DeepSeek Harness 之后，**左侧栏**会出现一个「**长期记忆**」入口（和「插件」「上下文洞察」「技能中心」同一列），点开就是面板：

- 五个分页：**必须遵守** / **行为设定** / **用户画像** / **可选遵守** / **变更日志**——全部中文，不用看文件名。
- 直接改，点「保存这一节」。**保存后立即生效，不需要重启**。
- 保存后底部会给出结果，例如「已生效：这一节会注入（约 320 字）」或「目前这一节是空的（只剩标题或注释），不会注入」。
- 有未保存改动的分页会显示一个小黄点；「放弃改动」可一次性还原。
- 面板只认这五个文件名，其它路径一律拒绝；单个文件上限 256 KB。
- 顶部还有一个「**自动采集记忆：已开启 / 已关闭**」开关，**点一下立即生效、不用重启**（详见下面 `autoCapture` 一节）：打开后 AI 会在对话里主动提议值得长期记住的偏好。它只影响 AI 提不提议，提议照旧要用户点「采纳」才算数。

### 待确认区（面板里的「待确认」分页）

这是 AI 与用户之间的一个**闸门**：

1. AI 用 `memory_suggest` 提议一条：目标文件 + 完整措辞 + 理由。**这个工具不写任何记忆文件**，只在 `<DSH_HOME>\memory-suggest.json` 里放一条 `pending`。
2. 用户打开面板 →「待确认」→ 看到卡片。卡片下方有一个**「补充说明」输入框**（可选）：想额外加的要求、想改的措辞，写在这里。
   - **打字不落盘**：输入框里的字只在点「采纳」的那一刻才随这条存下来（存进 `userNote`），所以犹豫期间磁盘上没有任何痕迹；5 秒一次的自动刷新也不会擦掉正在打的草稿。
   - 采纳后这一条会带着补充一起交给 AI，**与 AI 原文冲突时以补充为准**。补充上限 1000 字符，会自动去掉首尾空白。
3. 点「**采纳**」或「**忽略**」。**只有采纳之后**，用户下一次发消息时 AI 才会收到一条 `<MEMORY_SUGGESTION_ACCEPTED>` 通知（带着采纳的原文和补充）；AI 到那时才总结措辞、写进记忆文件，并调用 `memory_suggest_done` 记账。
4. **反悔窗口**：采纳之后、AI 下一轮还没开始之前，卡片状态是「已采纳 · 可撤销，等 AI 下一轮写入」，并多出一个「**撤销采纳**」按钮。点它这条回到 `pending`，补充原样留着，可以改完重新采纳。
   - 一旦通知已经交到 AI 手里（状态变成「通知已送达 · 处理中」），撤销按钮就没了，并说明原因——此时改主意直接在对话里说。
   - 如果点撤销的那一刻 AI 刚好开跑，服务端会如实拒绝并告知没能撤销。
5. 两种例外 AI 会**先停下把 diff 摆出来**：措辞与用户采纳的原文有实质差异；或这条与文件里已有内容重复、冲突。

页签上有数字气泡显示待确认条数；待确认分页每 5 秒自动刷新（可以一边聊天一边看）。**沉默 = 放弃**：提议完 AI 就回去干手里的活，不催促。

| 工具 | 干什么 | 会不会写记忆 |
|---|---|---|
| `memory_suggest` | 提议一条（文件限那五个，正文上限 4000 字符，单条可带一句理由） | **不会** |
| `memory_suggest_done` | 处理完一条后记账：写进了哪个文件，或为什么不写 | **不会** |

├── agent.md           行为设定           ← 注入

## 注入规则（决定它花多少 token）

| 行为 | 说明 |
|---|---|
| 注入位置 | 系统提示词的一个段落，`order = -500`：**Harness 身份之后、人格设定之前** |
| 顺序 | 必须遵守 → 行为设定 → 用户画像 → 可选遵守 |
| `<!-- -->` 注释 | **永远不注入**。所以模板里的说明文字不占上下文、不干扰 AI |
| 只有标题没有正文 | **整节不注入**。空文件 = 零开销 |
| 文件都没内容 | 整块不注入，一个字符都不占 |
| token 成本 | 记忆不变时系统提示词逐字节不变 → **吃满 prompt cache**；改了才会有一次新快照 |
| 预算 | 默认 6000 字符，超了按节截断并注明「已截断」 |
| `autoCapture` | 默认关。关着时一个字都不多注入；打开后末尾多一段**固定**提醒，且**不算进 6000 预算**。面板顶部的开关就是它，且**优先级高于这里** |
| 第二段（临时记忆） | `order = -490`，紧跟在这一段之后，有**自己的** `tempMaxChars` 预算；只有 `status: open` 的条目进，归档即消失。默认整段不存在 |

## 临时记忆（跨对话的活跃工作集）

长期记忆是**用户写、给 AI 长期遵守的**；临时记忆是**这一阵子没做完的活**——它存在的三个理由：

1. **跨对话交付**：一个对话做到一半，换另一个对话接着做，不用重讲背景。
2. **阶段性目标**：近期目标挂在这里，多个对话并行时不用反复说明。
3. **等待项**：等某个条件满足再执行的事，先记下来，别丢。

三种条目：

| kind | 用来干什么 | 什么时候清掉 |
|---|---|---|
| `handoff` 交接 | 一件事交到别的对话手里（换会话执行）。**正文可以写长、写全：它同时就是交付文档** | 接手方做完后归档 |
| `stage` 阶段目标 | 眼下的阶段性目标，省掉在多个对话里重复说明 | 阶段结束 |
| `waiting` 等待项 | 等条件满足再执行（CI 绿了、文件到了、用户确认了……） | 条件满足、执行完 |

要点：

- **只在用户要求时写**。工具描述里写死了：只有用户说出「写临时记忆 / 记到临时记忆 / 交付记忆 / 换会话执行 / 下次对话接着做」，AI 才调用它；**其余一律不调**——不自动总结、不顺手记、不后台回写。长期记忆那条「AI 从不自行写入」的不变量，这一层同样成立。
- **完成即清理**。调用 `temp_memory_done` 之后它**立刻不再注入**，从下一个模型步骤起零开销；数据留在盘上做归档，要物理删除得在面板里点「真正删除」。
- **存在 `<DSH_HOME>\temp-memory.json`**，不在记忆目录里——它要跨对话，就得让所有会话共用一份。**只有第一次写入时才创建这个文件**：光打开开关，磁盘上什么都不多。
- **预算独立、超了只点名**：`tempMaxChars`（默认 1200）只管这一层，与四层正文的 `maxChars` 互不挤占。装不下整条的条目**不会被截一半塞进去**，而是只留一行 `#id 全文见 <路径>`——半截的交付文档比一个指针更糟。
- **最新优先**：预算不够时，最晚更新的一条先保住。
- **文本是常量**：没条目时整段不注入；有 `waiting` 时才追加一小段固定提醒。**绝不把时间、条数之类每轮都在变的东西写进注入文本**，否则系统提示词每轮都变，prompt cache 每轮失效。
- **它不保证「到点自动执行」**。DSH 没有常驻观察者，没人能在后台盯着条件：`waiting` 条目做到的是「AI 在对话里能看到它，条件满足就直接做、做完归档，没满足不反复追问」。要真正的定时/条件触发，用 `schedule_create`，本插件**不做也不假装能做**。

| 工具 | 干什么 | 会不会写记忆 |
|---|---|---|
| `temp_memory({kind,title,body})` | 写一条，返回编号；**下一个模型步骤就出现在上下文里** | 只写 `temp-memory.json`，不碰那五个记忆文件 |
| `temp_memory_done({id,note})` | 归档一条（`note` 写结果），**立刻停止注入** | 同上 |

面板里多了第六个分页「**临时记忆**」（`tempMemory: true` 时才出现）：看 / 改 / 新增 / 归档 / 撤销归档 / 真正删除，一处点完，**不用重启**。「待确认」分页仍然固定在最后一个。

## 让 AI 写记忆（两条流程）

1. **「记住…」** → AI 把内容整理成条目，**先把 diff 摆出来**，用户确认后才落盘。
2. **「整理记忆」** → AI 把这段时间的沉淀批量整理出来，同样先给用户审。

## 配置

在 profile 的 bundle patch 里（`cordis.patch.yml`）：

```yaml
- insert:
    - id: user-memory
      name: 'dsh-user-memory'
      config:
        enabled: true     # false = 停用注入，不卸载
        dir: ''           # 空 = <DSH_HOME>/memory
        maxChars: 6000    # 注入总预算（含前言与截断提示）
        autoCapture: false  # true = 打开「记忆采集提醒」，见下节
        tempMemory: false   # true = 再挂一段「临时记忆」（跨对话活跃工作集）
        tempMaxChars: 1200  # 只给上面那一段的预算，与 maxChars 互不占用
```

改完需要**重启**才对 composition 生效；只改记忆文件内容则不需要。

在已有 profile 里打开临时记忆（**键要写全**，原因见下面那条实测注意）：

```yaml
# C:\Users\Adler\.dsh\profiles\desktop\cordis.patch.yml
- id: user-memory
  disabled: false
  config:
    enabled: true
    dir: ''
    maxChars: 6000
    autoCapture: false
    tempMemory: true
    tempMaxChars: 1200
```

> **实测注意：profile 里的 `config:` 是「整块替换」，不是逐键合并。**
> 在 `C:\Users\Adler\.dsh\profiles\<profile>\cordis.patch.yml` 里写 `- id: user-memory` + `config:` 时，列出的键会**顶掉** bundle 里的整套 config。比如只写 `autoCapture: true`，`dsh <profile> --dump-config` 读回来就是 `config: { autoCapture: true }` —— `dir` 和 `maxChars` 都不见了（退回内置默认值）。
> 所以覆盖时**把需要生效的键一次写全**：`enabled` / `dir` / `maxChars` / `autoCapture` / `tempMemory` / `tempMaxChars`。
> （`desktop` profile 归 Electron 应用专管，`--dump-config` 会直接拒绝，所以它这份只能靠重启后看效果——面板里那个新分页出现、且不是「未启用」就是生效了。）

### `autoCapture`：要不要让 AI 主动提建议（默认关）

**默认 `false`。关着的时候，注入的提示词与没有这个开关时逐字节相同——一个字符都不多。**

#### 开关在面板里，点了立刻生效

面板顶部有一个「**自动采集记忆：已开启 / 已关闭**」按钮（**不用切分页，打开面板就在**），点一下就切换。**不需要重启 App，也不需要改任何配置文件**——它写的是 `<DSH_HOME>\.autocapture` 这一个文件（内容就是一个 `on` 或 `off`），宿主每轮读到它就把注入段落同步过去，**下一次发消息**时就能看到效果。

状态从哪来，按钮下面的小字会说明：

| 小字 | 意思 |
|---|---|
| 「当前状态来自插件配置」 | 还没人点过面板，状态由 `config.autoCapture` 决定 |
| 「开启后，AI 会在对话里主动提议值得长期记住的偏好——提议只进「待确认」，用户点「采纳」才会写进记忆。」 | 面板点过了：**面板优先于配置**，而且**跨重启保留** |

优先级顺序：`.autocapture` 文件 > `config.autoCapture` > 内置默认 `false`。文件里写了 `on`/`off` 以外的内容（例如手改坏了），等于「没有意见」，自动退回看配置——不会因为一个字写错就静默关掉整个功能。

> 这个开关**只动注入文本**：它不写记忆文件、不碰待确认区、不改任何记忆内容。「AI 从不自行写入」照旧。

#### 也可以走配置文件（老办法）

把 `config:` 里的 `autoCapture` 写成 `true`，然后**重启 App**。适合一开始就想默认打开、或者要写进 dotfiles 的场景。

> 注意：一旦在面板上点过开关，`.autocapture` 文件就存在了，之后**它会一直盖住配置文件**——想交还给配置，删掉 `<DSH_HOME>\.autocapture` 即可。

打开后，注入段落的**末尾**会多出一小节固定文本：

```
## 记忆采集提醒（开关已打开）

- 本次对话中若发现值得长期记住的用户偏好或规则（明说的要求、反复出现的偏好、明确的禁止项），调用 `memory_suggest` 把它放进待确认区。
- 不要直接改记忆文件：用户点了「采纳」才会真正写入。
- 只提你确实观察到的，不要为了凑数而提。
```

> 它做的是「提醒模型自己去调 `memory_suggest`」——**只影响 AI 会不会主动提议，闸门本身不变**：提议仍然只是往待确认区放一条 `pending`，仍然要用户在面板里点「采纳」才会真正写进记忆文件。

几个要点：

| | |
|---|---|
| 不占预算 | 这段提醒**不算进 `maxChars`**（6000 是给那四层正文的），所以打开它不会挤掉记忆内容 |
| 文本是常量 | 内容写死在插件里，**绝不随对话变化**——否则系统提示词每轮都变，prompt cache 每轮失效，比多这几十个字贵得多 |
| 只是提醒，不是强制 | 它是「提醒模型去调工具」，**不保证每轮都调**，也不会让 AI 越权直接写文件。真觉得它总忘，再考虑叠加别的兜底（当前没有） |

## 自测

```
node test/selftest.mjs        # 52 项：注入与服务端（含面板开关）
node test/suggest-test.mjs    # 48 项：待确认闸门 + 补充框 + 撤销
node test/temp-test.mjs       # 72 项：临时记忆（第二段注入、工具、预算、归档、面板接口、跨对话）
node test/panel-test.mjs      # 66 项：面板 UI（需要 react + jsdom，见下）
```

`selftest.mjs`：注入位置与顺序、注释剔除、空节不注入、预算截断、停用行为、**`autoCapture`**（关闭时逐字节等于「没有这个字段」，打开时只在末尾追加常量提醒且不占 6000 预算；**面板开关**能即时开关注入、跨重启保留、优先于配置、手改坏的状态文件退回看配置、拒绝非布尔值，且**不点开关时绝不自己创建状态文件**），以及**面板接口**（读取、保存、拒绝非法文件名、拒绝非文本、畸形请求体不崩、注入反馈文案）。

`suggest-test.mjs` 盯的是**闸门最要紧的那条不变量**：提议绝不碰记忆文件；只有 `resolveSuggestion` 能改状态；非法决定与未知编号被拒；**内部步骤（压缩、起标题等）吃不掉一条采纳**，只有带真实用户消息的那一步才送达；注入的是一条 ours 的、冻结的 user 消息；重启后待确认区与编号延续；**补充**（采纳时写入、去除首尾空白、1000 字截断、空补充不写、编辑后以最新一条为准、随通知原文一起交给 AI）与**撤销**（仅 `accepted` 可撤销 → 回到 `pending`、保留补充、丢掉 `decidedAt`；`pending` 与 `delivered` 一律 409；未知编号 404）。

`temp-test.mjs` 盯的是**那第二段**：默认关闭时**连注册都不发生**（分页、工具、文件一个都不多，等于 0.6.0 的行为）；打开后固定是**两段**、`-500` 在前 `-490` 在后；写入门槛写死在工具描述里（只在用户明确要求时调，非法 kind / 空标题 / 空正文一律拒绝）；写入**下一个模型步骤就进上下文**；`temp_memory_done` 之后**立刻不再注入**而归档仍在盘上；只有 `waiting` 打开时才追加那段常量提醒、关掉就消失；超预算的条目**只点名不半截注入**且点名里带 store 路径；`tempMaxChars` 与 `maxChars` 互不挤占（含「预算小到装不下任何一条」退化为静默）；归档最多 20 条、**未完成的一条永远不剪**；面板七个动作（读 / 新增 / 编辑 / 归档 / 撤销归档 / 真删 / 清理归档）与停用时的拒绝；**一个会话写完，另一个会话直接看到同一条，归档也共享**；并**钉住**那条已知边界：手改 `temp-memory.json` 运行中不生效、下一次写入会覆盖它。

`panel-test.mjs` 在 jsdom + React 里**渲染真实的面板组件**，像浏览器一样点分页、打字、点「采纳」「撤销采纳」、点顶部的采集开关、手动触发 5 秒轮询，断言：待确认卡片有补充框且初始为空、打字不发任何请求、采纳把补充一起发出去、采纳后变成只读展示 + 出现撤销按钮、撤销后回到输入框并保留草稿、轮询不擦草稿、已送达的卡片没有再撤销的入口；**采集开关不切分页就能看到、显示的是宿主报来的真实状态、点击发 `on:true/false`、按钮与说明文字随之翻转、配置来源与面板来源的文案不同**。

它需要的 `react` / `react-dom` / `jsdom` **故意不是本插件的依赖**（本插件零依赖、无构建步骤）。想让面板测试真的跑起来，装到一个临时目录再指给它（没设 `UMEM_UI_DEPS` 时它会打印 SKIP 并以 0 退出，CI 因此保持无依赖）：

```
npm install --prefix P:\_temp\umem-deps react@19 react-dom@19 jsdom@26
$env:UMEM_UI_DEPS = 'P:\_temp\umem-deps\node_modules'
node test/panel-test.mjs
```

改完代码先跑这四个（改了 `index.js` 或 `client.js` 还要重启 App 才生效）。

## 完全卸载 / 回退

```
plugin_manager  remove_bundle  dsh-user-memory
```

插件消失，**记忆库 `C:\Users\Adler\.dsh\memory\` 不会被删**（数据与代码分离）。想彻底清干净就再手删那个目录。

## 已知边界（必须说清）

1. **「必须遵守」不是技术强制**。插件只能把规则放进系统提示词的强位置，不能让模型永不失误。写得具体、可判定、够短，比写得多更有效。
2. **改代码需要重启**。加载器用裸 `import()`，Node 的 ESM 模块缓存按路径记账且不失效——改 `index.js` 或 `client.js` 后必须重启 App。**改记忆文件不需要**。
3. **两个 profile 互相独立**。`desktop`（桌面版）与 `web`（网页版）各有自己的 node_modules；这个插件目前只装在 `desktop`。
4. **界面文案硬编码中文**。不走 locale 服务——单语言自用插件的取舍（`locale/` 里有 en/zh 两份 JSON，但面板文案不读它）。
5. **临时记忆不跨进程同步**。`temp-memory.json` 由**拥有它的那个进程**在内存里维护（一个 App 进程托管所有对话，所以正常用法没问题）。手改这个文件、或同时跑两个进程（例如 desktop 与 web 各一份）时：磁盘上的改动要**下次启动**才生效，而且**下一次写入会覆盖手改的内容**——要改它请用面板。
6. **`waiting` 不是调度器**。没有常驻观察者，条件是否满足由 AI 在对话里判断；要真正的定时/条件触发请用 `schedule_create`，本插件不做，也不假装做了。
