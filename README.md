# dsh-user-memory

自研的 DeepSeek Harness 插件：把**你本人编写**的分级长期记忆注入到我的系统提示词里，并提供一个**中文图形面板**让你直接看和改。

- **不是 skill**，是宿主插件（Host plugin）——只要 profile 加载它，每轮都在。
- **运行时只读**（除非你操作）。它永远不自己写你的记忆：只有两种写入——你在面板里点保存，或你让 AI 用文件工具改。没有任何自动采集、自动总结、后台回写、网络访问。
- **AI 只能"提议"，不能"决定"**：我可以把一条修改建议放进「待确认」区（`memory_suggest` 工具），但**只有你在面板里点「采纳」，它才会变成一条通知、让我下一轮去写**。见下面「待确认区」。
- **零依赖**，只用 Node 内置模块。整个目录拷到哪都能跑。

## 图形面板（推荐用这个）

重启 DeepSeek Harness 之后，**左侧栏**会出现一个「**长期记忆**」入口（和「插件」「上下文洞察」「技能中心」同一列），点开就是面板：

- 五个分页：**必须遵守** / **行为设定** / **用户画像** / **可选遵守** / **变更日志**——全部中文，不用看文件名。
- 直接改，点「保存这一节」。**保存后立即生效，不需要重启**。
- 保存后底部会告诉你结果，例如「已生效：这一节会注入（约 320 字）」或「目前这一节是空的（只剩标题或注释），不会注入」——**你一眼就知道这次改动到底有没有用**。
- 有未保存改动的分页会显示一个小黄点；「放弃改动」可一次性还原。
- 面板只认这五个文件名，其它路径一律拒绝；单个文件上限 256 KB。

### 待确认区（面板里的「待确认」分页）

这是给我和你之间的一个**闸门**：

1. 我用 `memory_suggest` 提议一条：目标文件 + 完整措辞 + 理由。**这个工具不写任何记忆文件**，只在 `<DSH_HOME>\memory-suggest.json` 里放一条 `pending`。
2. 你打开面板 →「待确认」→ 看到卡片 → 点「**采纳**」或「**忽略**」。
3. **只有采纳之后**，你下一次发消息时我才会收到一条 `<MEMORY_SUGGESTION_ACCEPTED>` 通知（带着你采纳的原文）；我到那时才总结措辞、写进记忆文件，并调用 `memory_suggest_done` 记账。
4. 两种例外我会**先停下把 diff 摆给你看**：我的措辞与你采纳的原文有实质差异；或这条与文件里已有内容重复、冲突。

页签上有数字气泡显示待确认条数；待确认分页每 5 秒自动刷新（可以一边聊天一边看）。**沉默 = 放弃**：提议完我就回去干手里的活，不催你。

| 工具 | 干什么 | 会不会写记忆 |
|---|---|---|
| `memory_suggest` | 提议一条（文件限那五个，正文上限 4000 字符，单条可带一句理由） | **不会** |
| `memory_suggest_done` | 处理完一条后记账：写进了哪个文件，或为什么不写 | **不会** |

## 记忆库在哪（也可以直接改文件）

```
C:\Users\Adler\.dsh\memory\
├── rules-must.md      必须遵守（硬性）   ← 注入
├── agent.md           我的行为设定        ← 注入
├── profile.md         用户画像            ← 注入
├── rules-should.md    可选遵守（酌情）    ← 注入
└── log.md             变更日志            ← 不注入，只给你自己记账
```

直接记事本改也行，效果与面板完全一样——**文件是唯一真相**。

## 注入规则（决定它花多少 token）

| 行为 | 说明 |
|---|---|
| 注入位置 | 系统提示词的一个段落，`order = -500`：**Harness 身份之后、人格设定之前** |
| 顺序 | 必须遵守 → 行为设定 → 用户画像 → 可选遵守 |
| `<!-- -->` 注释 | **永远不注入**。所以模板里的说明文字不占上下文、不干扰我 |
| 只有标题没有正文 | **整节不注入**。空文件 = 零开销 |
| 文件都没内容 | 整块不注入，一个字符都不占 |
| token 成本 | 记忆不变时系统提示词逐字节不变 → **吃满 prompt cache**；改了才会有一次新快照 |
| 预算 | 默认 6000 字符，超了按节截断并注明「已截断」 |

## 让 AI 帮你写（两条流程）

1. **「记住…」** → AI 把内容整理成条目，**先把 diff 摆给你看**，你确认后才落盘。
2. **「整理记忆」** → AI 把这段时间的沉淀批量整理出来，同样先给你审。

## 配置

在 profile 的 bundle patch 里（`cordis.patch.yml`）：

```yaml
- insert:
    - id: user-memory
      name: 'dsh-user-memory'
      config:
        enabled: true     # false = 停用注入，不卸载
        dir: ''           # 空 = <DSH_HOME>/memory
        maxChars: 6000    # 注入总预算（含前言与截断提示）
```

改完需要**重启**才对 composition 生效；只改记忆文件内容则不需要。

## 自测

```
node test/selftest.mjs        # 27 项：注入与面板
node test/suggest-test.mjs    # 28 项：待确认闸门
```

`selftest.mjs`：注入位置与顺序、注释剔除、空节不注入、预算截断、停用行为，以及**面板接口**（读取、保存、拒绝非法文件名、拒绝非文本、畸形请求体不崩、注入反馈文案）。

`suggest-test.mjs` 盯的是**闸门最要紧的那条不变量**：提议绝不碰记忆文件；只有 `resolveSuggestion` 能改状态；非法决定与未知编号被拒；**内部步骤（压缩、起标题等）吃不掉一条采纳**，只有带真实用户消息的那一步才送达；注入的是一条 ours 的、冻结的 user 消息；重启后待确认区与编号延续。改完代码先跑这两个。

## 完全卸载 / 回退

```
plugin_manager  remove_bundle  dsh-user-memory
```

插件消失，**记忆库 `C:\Users\Adler\.dsh\memory\` 不会被删**（数据与代码分离）。想彻底清干净就再手删那个目录。

## 已知边界（必须说清）

1. **「必须遵守」不是技术强制**。插件只能把规则放进系统提示词的强位置，不能让模型永不失误。写得具体、可判定、够短，比写得多更有效。
2. **改代码需要重启**。加载器用裸 `import()`，Node 的 ESM 模块缓存按路径记账且不失效——改 `index.js` 或 `client.js` 后必须重启 App。**改记忆文件不需要**。
3. **两个 profile 互相独立**。`desktop`（桌面版）与 `web`（网页版）各有自己的 node_modules；这个插件目前只装在 `desktop`。
4. **不改用 locale 服务**。界面文案是硬编码中文。这是有意取舍：单语言自用插件，省掉一层 locale 注册。
